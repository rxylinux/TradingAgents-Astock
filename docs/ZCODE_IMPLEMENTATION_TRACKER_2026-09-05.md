### 剩余验证边界与旧数据

1. **运行环境：** 未启动真实 SDK 模型子进程、未验证 Gemini、未构建 Docker 镜像。Windows 锁仅代码审查；POSIX 实际跨进程锁已验证。PDF 本轮新增用例验证内容流转，未新增字体/排版实机验收。
2. **历史行情与财报：** 财报缺少可靠披露/修订时间时保守返回缺失；没有全面联网核对上游字段与数据质量。部分市场实时排名采用明确禁止用于历史分析的提示，尚未改造成完整的历史排名数据源。第二批测试曾出现一次 Yahoo 后备取数，具体经过见上文，不能宣称整个整改过程从头到尾绝无网络请求。
3. **旧记忆：** 旧短窗口结算只提供诊断与迁移说明，没有自动重写真实决策、收益或反思。财报缓存已切换新版本/作用域，未清空用户历史目录；旧记录是否需要重算仍需按批次 2 的迁移说明有范围地处理。
4. **断点兼容：** 旧共享消息/旧汇合拓扑断点继续明确拒绝并保留；不能把它们当成可无损迁移。已有分支隔离但缺集合元数据的旧断点，可以按同一实际图继续，原团队无法完整反向验证，恢复时应保持原选择。新断点新增团队匹配校验，但没有覆盖模型、数据源、窗口等全部配置指纹。
5. **历史索引：** A11 保证有有效断点的新失败任务不被旧报告隐藏；没有实现同标的同日期多运行的独立 run_id。历史页面按 Web 当前配置的结果目录查询，不会自动聚合任意 Python API 调用指定的其他目录。

这些边界是验收范围与旧数据处理约束，不能用“测试全绿”替代生产环境验证。
