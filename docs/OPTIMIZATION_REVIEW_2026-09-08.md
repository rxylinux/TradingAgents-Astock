## 一、优先修复的具体问题

### P1：宏观新闻没有按分析时点过滤

位置：`tradingagents/dataflows/a_stock.py:1634`，特别是 `:1713` 的输出循环。

`get_global_news(curr_date, look_back_days, limit)` 计算了起始日期，但实际请求最新快讯，返回时只去重并截取数量，没有按记录时间过滤，输出正文还省略了原始发布时间。

**已通过正式工具入口离线复现**：对 `get_global_news.invoke()` 传入 `curr_date=2026-01-01`，替身返回 `showTime=2099-01-01 10:00:00` 的 `FUTURE_EVENT`，最终仍输出：

```text
## China & Global Market News, from 2025-12-25 to 2026-01-01:

### FUTURE_EVENT (source: Eastmoney Global)
future evidence
```

影响：历史分析会把分析日之后的消息带入新闻/政策分析和下游辩论；报告标题会让这些消息看起来属于请求窗口。已有财务、资金流和记忆时点防护不能覆盖这条路径。

建议：

- 将解析时间、时区归一化、区间筛选放在去重和 `limit` 之前；输出保留发布时间及可获得的原始链接。
- 历史接口无法覆盖请求区间时，明确返回历史覆盖不足，不能把最新列表当历史结果。
- 正式运行的分析截止时点从运行上下文确定；验证模型传入日期不超出边界，不能完全依赖提示词传参。
- 对缺失/无效时间记录标记 `unknown`；历史研究默认排除这些记录，保留排除原因和数量。

验收：分析日前、当日、之后、缺失时间、非法时间、跨时区记录；先过滤再限量；真实 `@tool → route_to_vendor → vendor` 调用链；个股和指数使用入口。

### P1：个股新闻仍混淆请求失败与成功空结果

位置：`tradingagents/dataflows/a_stock.py:1584–1603`。

两项已复现行为：

1. 东财和新浪同时抛出 `TimeoutError`，返回普通字符串 `No news found for A-stock '600519'`，`_is_failure_output()` 判为 `False`。
2. 返回一条 `time='bad-date'` 的新闻，`get_news.invoke()` 的历史区间查询仍包含该新闻，因为时间解析异常后执行 `pass`。

影响：数据源不可用会被表达为“没有新闻”；无法证明在当时可知的记录仍进入历史分析。此函数当前没有 `cached_data` 装饰器，因此本次并未证明这里存在失败缓存污染；已证明的是错误语义和时点放行。

建议：沿用已有 `DataFailure` 承接失败，记录每个来源的成功、失败和空结果。至少一个来源成功但无记录可返回成功空结果，同时保留部分来源失败的限制；全部失败应返回失败。逐步在工具内部增加 `ok / empty / unavailable / partial` 状态，再由兼容渲染层输出文字。

验收：双失败、成功空、主失败后备成功、主成功空后备失败、缺失时间、未来记录；下游质量限制必须看得见失败，不能只在日志里有告警。

### P1：限流重试叠加，单次逻辑调用可变成 30 次请求

位置：`tradingagents/llm_clients/openai_client.py:32`、`:265`。

外层 `NormalizedChatOpenAI.invoke()` 最多调用父类 5 次；客户端默认 `max_retries=5`，即每次父类调用可包含首次请求及 5 次重试。

**已离线复现**：使用 `httpx.MockTransport` 持续返回 HTTP 429，并把 sleep 替换为空操作；一次 `.invoke()` 发出 **30 次传输请求**后抛出 `RateLimitError`。这只说明该持续限流场景的尝试次数，不代表正常调用都会如此，也不等于产生了 30 次成功计费。

此外，`agents/utils/structured.py` 捕获结构化调用的任意异常后再走纯文本生成。这个后备有助于处理格式不兼容，但鉴权、预算耗尽、超时和取消等异常不应不加区分地进入新一轮调用。

建议：

- 在一个明确层级管理总尝试次数；区分可重试错误、认证/参数错误、结构化解析失败和取消。
- 为运行和角色设置截止时间、工具循环/调用上限；等待重试前检查剩余预算和停止信号。
- 将 provider timeout / retry 配置真正从图入口传给客户端；当前 `_get_provider_kwargs()` 没有转发这两项。
- SDK 及跨供应商后备纳入同一预算，保留实际调用来源。

验收：持续 429 下总尝试数符合统一上限；401/无效参数快速失败；重试等待可停止；结构化后备不重置预算；失败尝试也有记录。

## 二、性能与运行可观测性

### P2：共享数据采集，抑制并发重复请求

位置：`dataflows/cache_utils.py:215–270`、`dataflows/a_stock.py:558`、`agents/analysts/*.py`。

缓存的读写分别加锁，但“检查未命中 → 取数 → 写入”之间没有按 key 合并正在执行的请求。对同一参数启动 7 个并发调用，离线屏障实验观察到底层函数执行 **7 次**。

这是缓存装饰器的能力缺口；实际外部重复次数还取决于角色选择、工具参数和缓存状态。个股新闻、宏观新闻当前也未使用该通用缓存，而新闻、政策、情绪、游资、解禁存在重叠取数需求。东财请求入口又串行持锁执行网络请求，重复请求会增加等待。

建议先优化相同工作量：

1. 对相同源、参数和时点的请求实现 single-flight：首个调用取数，其他调用等待并共享结果。异常时释放等待者，失败后允许新请求。
2. 在每次运行内共享不可变数据包；不同角色继续保留独立工具消息，只共享数据。保留已有数据源配置与目录隔离。
3. 缓存 key 规范化参数和日期，加入来源及格式版本；不要仅用原始 `args/kwargs` 字符串区分语义相同的调用。
4. 保留供应商节流约束，测量命中率、合并次数、等待耗时、外部调用次数及端到端 P50/P95，再决定是否调整并发。
5. OHLCV CSV 存在直接读写路径，可另行增加原子发布和同文件互斥的回归验证；本次未复现 CSV 竞争损坏，不能将其列为已确认故障。

后续可试验统一获取 K 线并一次计算多项指标，减少反复读 CSV 和重复计算；在数据包中记录实际覆盖区间及是否包含未收盘数据。

### P2：把运行统计移到核心层并持久化

位置：`cli/stats_handler.py`、`web/runner.py:255`、`graph/trading_graph.py:1061`。

目前 Web 从 CLI 导入统计回调；该回调累计调用和 token 数，正式报告存档没有完整的逐调用统计账本。N02 配置快照记录了配置，不证明实际采用哪个后备供应商。

建议新增核心运行事件记录，并绑定现有 `run_id`：角色、模型/实际 provider、开始结束、等待/请求耗时、成功失败、重试/后备、token、缓存命中。token 或费用缺失记为未知；费用保留币种和价格版本。用该数据生成 N04 submission 的 observations，避免手工填充。恢复时按事件身份去重，已消耗预算不能归零。

运行状态采用 `running → stopping → stopped`。当前 `web/runner.py:340` 阻塞在 `next(stream)` 时，停止标记要等调用返回后才能检查；`request_stop()` 又立即清空展示统计。这不构成对在途网络调用的即时取消。建议保留已发生统计，阻止新调用，对在途请求使用支持取消的传输或截止时间；UI 如实显示“正在停止”。本项为源码路径分析，本次未做真实服务取消实验。

## 三、提升研究质量的下一步

### 先建立证据链，再比较模型和角色配置

`agents/quality_gate.py:62` 的 A/B/C/D/F 主要检查长度、表格和失败标记。当前 UI 明确称为完整性检查，这个边界应继续保留。长报告附表格能通过检查，并不说明其中事实已经核验。

建议把原路线图 N07 的最小证据结构提前：

```text
工具采集 → 时点过滤与规范化 → 本次运行的证据包
         → 各分析师提取事实/解释 → 多空分歧 → 决策
```

每条证据存 `evidence_id`、来源、发布时间/可知时间、采集时间、覆盖区间、单位、原始摘要/hash；没有真实来源字段就记未知。事实声明引用证据 ID，区分事实与推断。同一新闻被多个角色复述，只算同一份证据。报告和结构化决策均保留证据引用，文字渲染作为展示出口。

### 用现有 N04 做受控对比

`examples/evaluation/README.md` 明确现有示例为 6 个合成案例 × 2 trials，用于验证评测流程。`performance.py` 也明确当前收益统计不是可交易组合回测。

建议首批构建 20–30 个固定数据案例，覆盖正常个股、资料稀缺、指数、重大事件和历史日期，每套配置重复 3 次。这个规模用于发现回归，不足以证明投资有效性。案例证据包一旦冻结，模型比较时不能重新拉取不同的实时数据。

优先实验：

- 默认七角色与精简角色预设：比较遗漏、重复证据、无依据声明、评级波动、token 和耗时。
- 单轮与更多轮辩论：检验额外调用是否减少错误/补足反证。
- 统一模型与角色模型配置：固定其他变量，检查差异是否稳定。

只在实验支持时调整默认角色、模型或轮次。提示词中的数据不足、反证条件可以先规范；加入额外 Agent 的收益要由同一案例集证明。

对预测有效性的判断需另做前瞻样本及严格时间切分，处理执行时点、交易约束、成本、样本选择和重叠持有期；不能用本轮完整性或人工标注支持率代替。
